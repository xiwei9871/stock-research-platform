# M1 存储与运行开销估算（隔离实测外推）

## V2 EOD 写入

- 单日行数 ≈ universe 5,213 → UPDATE ~5.2k 行/日；
- 演练 3 日 15,569 行 UPDATE 秒级完成；P1d.3 实测引擎 ~19k 行/s；
- 每交易日新增 WAL ≈ 行宽×5.2k ≈ 数 MB —— 可忽略。

## finver 事件层

- 每 raw payload 展开 ~58 行（16,586 载荷→959,839 期行）；
- 事件行 ≈ 观测到的不同指纹数；稳态日常增量 ≈ 每期每资产每端点 1 事件 + 偶发重述版本；
- 演练 6 资产 → 228 events / 223 keys；全量 5,213 资产 × ~3 端点 × ~180 期 ≈ 上限 ~2.8M keys（一次性回放），日常抓取增量仅当前期 ~15k 事件/批；
- 单 event ≈ metrics jsonb 1–3KB → 全量回放 ~3–8GB；**建议 M2 分批回放 + metrics 只存 diff 或受控字段集**（当前设计已支持字段裁剪，回放脚本按需裁剪）。

## finver 读

- `latest`：key_chain 直读 O(1)；`read_as_of`：索引 (asset,st,period,seq)。

## 结论

增量成本可忽略；一次性历史回放为 GB 级一次性任务（M2 审批内）。
