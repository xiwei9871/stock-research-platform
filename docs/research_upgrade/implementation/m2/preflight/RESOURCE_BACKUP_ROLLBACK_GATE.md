# M2-0-E — 资源、备份、恢复与回滚核验

## E1 资源量化

| 项 | 估算 | 依据 |
|---|---|---|
| V2 增量日写入 | ~5.2k 行/交易日（5 列 UPDATE，无新行） | 生产日级资产数 × 列宽 |
| T4 回填规模 | 17.3M 行 UPDATE，分批（每日期一事务） | count 实测 |
| WAL 增量 | UPDATE 全行镜像 → 与表体积同量级 **~3GB+**（无归档，驻留 pg_wal 目录） | PG full-page write 特性 |
| 单批耗时 | 每日期 ~5k 行 UPDATE，秒级/批；全量时长**不承诺** | 测试库 8 行/批毫秒级，不可外推；shared_buffers=128MB 偏低 |
| 磁盘水位 | 库 686GB；回填前必须确认宿主磁盘余量 > ~10GB | 未取到宿主 df——入审批检查项 |
| finver 新增 | 事件行 ~载荷×行展开（参考 959,839 快照行级规模）+ observation/载荷 | P2.1 取证量级 |
| F4 回放 | 16,586 载荷、2.5GB 载荷列流式读，分钟~小时级 | 实测体量 |
| EOD 窗口冲突 | V2 stage 排在基础构建后，避开 20:00-22:00 策略发布窗（增量仅秒级） | cron 时序 |

P1d.3 的 1.22M 行演练性能**仅作外推参考**，不代表生产。

## E2 备份核验 — RESTORE_NOT_VERIFIED

| 项 | 实测 |
|---|---|
| 最近可用备份 | **未发现**（仓库/cron/launchd 无 pg_dump、无归档、副本 0） |
| 类型/覆盖/保留 | 无 |
| 恢复演练证据 | 无 → `RESTORE_NOT_VERIFIED` |

**硬性前置**：T4 与任何大批量写动作执行前，必须先落一次 `pg_dump -Fc core.asset_status_daily`（或宿主快照）并记录校验。**在证据存在前，T4 保持 BLOCKED。**

## E3 回滚分级

| 级 | 动作 | 适用 |
|---|---|---|
| R1 功能关闭 | enabled=False | V2 写、finver 写——**默认首选** |
| R2 代码回退 | 回滚部署版本 | T2/F2 |
| R3 增量停止+checkpoint | kill 回填，checkpoint 保留续跑 | T4/F4 |
| R4 数据/Schema 修复 | 版本标记清理、DROP（仅未写数据时） | 兜底，需单独审批 |

- **不得把 DROP COLUMN 当作写入大量 V2 后的默认回滚**——数据保留优先；
- finver 事件是审计证据，部署后**原则上不删**，关闭消费者≠删事件表。

## E4 演练边界核验

- 独立实例 `stock_m2_test`（本机 PG16）承载全部写入演练 ✅；
- `m1_shadow` 位于生产库——本轮未向其写入；历史演练产物归属 M1 授权范围，如实注明；
- 所有故障注入/并发/回滚测试均在独立实例完成。
