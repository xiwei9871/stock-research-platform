# v0.1 Local EOD Research Baseline

Release date: 2026-06-16

## Positioning

`v0.1-local-eod-research-baseline` is a local EOD stock research baseline for
human decision support. It is designed for daily post-market data refresh,
candidate review, evidence aggregation, operator decisions, and later replay.

It is not an automatic trading system, real-time market monitor, broker
integration, production risk engine, capital management system, or multi-tenant
SaaS product.

## Included Capabilities

- `data_run_manifest` records module-level EOD status, tier, source, counts,
  warnings, errors, and artifacts.
- `run_summary.json` and `run_manifest.json` provide machine-readable daily
  status.
- Readiness v2 reports `OK`, `PARTIAL`, or `BLOCKED` from manifest and summary
  data.
- Review Queue exposes lineage including run id, trade date, source, score
  version, rank, evidence status, warnings, and digest links.
- Evidence Digest exposes section-level status for core and auxiliary evidence.
- Review item and Evidence Digest snapshots preserve the evidence payload used
  during review.
- EOD pipeline includes the Tier 2 `review_evidence_snapshots` post-step.
- Snapshot APIs support historical review and replay.
- Operator decision import and write API link decisions to snapshots when
  available.
- Stock Workspace includes a minimal local Operator Decision panel for
  non-execution research actions such as `watch`, `skip`, `follow_up`, `note`,
  `add_to_shadow`, and `close`.

## Not Included

- New strategy logic or new factor development.
- New external data sources.
- Automatic order generation or execution.
- Broker connectivity.
- Realtime or intraday streaming operations.
- Position sizing, portfolio execution, or production risk management.
- HomeCockpit redesign.
- Strategy Command Center, Backtest Lab, or vectorized backtest promotion into
  the v0.1 baseline.
- Multi-tenant SaaS concerns.

```text
Platform Readiness
-> Review Queue
-> Stock Workspace
-> Evidence Digest
-> Operator Decision Panel
-> Decision History / Operator History
```

## Readiness Rules

- `OK`: Tier 1 is usable, latest trade date is acceptable, TopN / Review Queue
  are available, and no blocking errors are present.
- `PARTIAL`: Tier 1 is usable but Tier 2 / Tier 3 evidence, reports, snapshots,
  or auxiliary modules are missing, partial, failed, skipped, or unavailable.
- `BLOCKED`: Tier 1 has a critical failure, core data is stale or undercovered,
  TopN is unavailable, or Review Queue cannot be formed.

Snapshot generation is Tier 2. Snapshot failures should produce `PARTIAL` when
Tier 1 remains usable.

## Review And Replay Loop

The v0.1 replay chain is:

```text
Review Queue item
-> Evidence Digest
-> review_item_snapshot / evidence_digest_snapshot
-> Operator Decision
-> Decision History
-> Follow-up / Outcome compatible readback
```

The platform preserves `run_id`, `latest_trade_date`, `digest_key`, snapshot
ids, payload hashes, and snapshot linkage status where available. Snapshot
missing is allowed for manual or historical decisions and is represented as a
warning rather than a failed decision write.

## Known Limits

- Local EOD data availability depends on the configured local database and
  upstream collectors.
- Auxiliary evidence can be partial without blocking the daily review.
- Snapshot coverage depends on Review Queue and Evidence Digest availability for
  the run.
- Some dashboard, strategy, backtest, and experimental files remain dirty in
  the working tree and are intentionally outside this baseline.
- Playwright end-to-end flow should be run only when local API/frontend fixtures
  are stable.

## Next Stage Principles

- Prefer stable daily operation over new features.
- Prefer data quality, freshness, coverage, lineage, and replayability.
- Keep strategy output framed as candidate evidence for human review.
- Do not introduce automatic trading or execution semantics.
- Do not continue open-ended feature batches until v0.1 operation has been
  exercised on real daily runs.
