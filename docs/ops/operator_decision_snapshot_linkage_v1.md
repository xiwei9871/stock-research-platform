# Operator Decision Snapshot Linkage v1

## Scope

Batch E links operator decision imports to the Review Queue and Evidence Digest snapshots generated by Batch C/D. The linkage is stored inside `source_context` JSON so existing `ops.operator_decision_event` schema and dashboard read APIs remain compatible.

## Out Of Scope

- No automatic trading, broker integration, execution status, or buy/sell/trade signal wording.
- No new strategies, factors, or data sources.
- No HomeCockpit, Strategy Command Center, Backtest Lab, or large frontend changes.
- No schema migration unless a future batch promotes linkage fields out of `source_context`.

## Current Decision Chain

- `operator_decision/journal.py` builds a manual review-only journal artifact from CSV-like inputs.
- `operator_decision/read_model.py::import_decision_journal` imports the journal into `ops.operator_review_session` and `ops.operator_decision_event`.
- `ops.operator_decision_event.source_context` is a text column and currently accepts plain strings or JSON strings.
- `dashboard/decisions.py` reads `source_context` and already exposes basic snapshot linkage fields when JSON contains snapshot IDs.
- Dashboard has read-only decision endpoints; there is no current dashboard POST write endpoint.

## Linkage Resolver

Implementation location:

`src/stock_research/operator_decision/snapshot_linkage.py`

Input fields:

- `review_item_snapshot_id`
- `evidence_digest_snapshot_id`
- `run_id`
- `digest_key`
- `trade_date`
- `asset_id`
- `stock_code`
- `score_version`
- existing `source_context`

Resolution order:

1. Use explicit snapshot IDs when supplied and found.
2. Use `run_id + digest_key` to find both snapshot tables.
3. Use `run_id + asset_id` as a best-effort fallback.
4. Prefer exact `digest_key`, then newest `created_at`.
5. Prefer evidence digest snapshot whose `digest_key` matches the review item snapshot.
6. Missing snapshots do not block import.

## source_context Structure

Existing `source_context` is parsed if it is JSON. If it is plain text, it is preserved under `source_context_label`.

New linkage fields are merged without overwriting unrelated existing keys:

```json
{
  "source_context_label": "dashboard_topn",
  "source_type": "score_topn",
  "source_name": "manual_v1_topn",
  "run_id": "eod-2026-06-12-local",
  "digest_key": "2026-06-12:manual_v1:000001.SZ",
  "review_item_snapshot_id": "review_item_snapshot:abc",
  "evidence_digest_snapshot_id": "evidence_digest_snapshot:def",
  "review_item_payload_hash": "sha256...",
  "evidence_digest_payload_hash": "sha256...",
  "snapshot_linkage_status": "linked",
  "snapshot_linkage_warnings": [],
  "review_item_as_of": "2026-06-12T18:30:00",
  "evidence_as_of": "2026-06-12T18:30:00"
}
```

## Missing Snapshot Behavior

If no snapshot can be found:

```json
{
  "snapshot_linkage_status": "missing",
  "snapshot_linkage_warnings": [
    "No review_item_snapshot found for run_id + digest_key",
    "No evidence_digest_snapshot found for run_id + digest_key"
  ]
}
```

The decision import still succeeds. This supports manual watchlist decisions, historical records, and EOD days where the snapshot post-step was not run.
