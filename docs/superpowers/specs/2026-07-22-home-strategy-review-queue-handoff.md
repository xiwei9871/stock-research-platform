# 首页策略卡片复盘队列跳转设计

## 目标

首页“启用策略表现”中的单策略操作应进入复盘队列，并自动定位到该策略。策略实验室继续由独立的“打开策略实验室”入口和侧栏入口承载。

## 交互契约

- 卡片按钮文案从“打开策略 {策略名}”改为“查看 {策略名} 复盘”。
- 点击官方策略卡片后进入 `/review-queue?strategy_id=<strategy_id>`。
- 复盘队列加载最新可用复盘数据后，优先选中与 `strategy_id` 对应的策略分组及其第一只候选。
- 对应策略分组即使暂时为空，也应保持选中并展示该策略的空状态。
- 缺失或无法匹配的 `strategy_id` 使用复盘队列原有的首个非空分组选择规则，不阻塞页面。
- LHB、Mid Trend、Tech Bottleneck 三个官方策略使用同一通用跳转契约。

## 边界

- 不修改策略计算、发布或后端复盘数据结构。
- 不删除策略实验室及其独立入口。
- 不把复盘队列选择状态写入后端。

## 验收

- React 单元测试验证 URL、按钮文案及指定策略初始选择。
- Playwright P0/EOD 一致性测试验证三个首页卡片都进入相应策略的复盘队列。
- 前端构建通过。
