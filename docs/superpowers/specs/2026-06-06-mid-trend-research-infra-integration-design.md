# Mid-Trend Research Infra Integration Design

## Goal

Integrate the completed `research_infra` method layer into one real workflow:
mid-trend portfolio review. The integration should add standardized evidence
artifacts beside the existing review outputs without changing the review logic,
portfolio logic, execution boundaries, or dashboard behavior.

## Scope

Included:

- A thin integration module that converts an existing mid-trend review result
  into research-infra artifacts.
- Standard run evidence bundle.
- Experiment registry JSONL record.
- Research signal records for research support, coverage freshness, and risk
  disclosure signals available in review rows.
- Attribution cards for review outcomes such as low-priority hold, coverage gap,
  replacement concern, and drawdown-control concern.
- JSON and Markdown sidecar artifacts under an integration output directory.

Excluded:

- Rewriting `mid_trend_portfolio_review.py`.
- Rewriting mid-trend attribution modules.
- Database migrations.
- Dashboard changes.
- Broker, order, execution, cash, account, position, or automatic promotion
  behavior.
- Bulk integration of all mid-trend modules in one pass.

## Architecture

Create a thin adapter module:

`src/stock_research/research_infra/mid_trend_integration.py`

The adapter accepts:

- `trade_date`
- `strategy_variant`
- `review_result`, produced by `build_mid_trend_portfolio_review_from_frames(...)`
- `output_dir`

It writes sidecar artifacts under:

```text
<output_dir>/research_infra/
  experiment_registry.jsonl
  research_signals.json
  attribution_cards.json
  attribution_cards.md
  run_card/
    ...
```

The existing mid-trend review continues to own:

- review row construction
- portfolio summary
- CSV output
- Markdown review output
- labels such as high-priority hold, low-priority hold, and discussion-only

The integration module owns only method-layer artifact conversion.

## Data Flow

1. Caller runs the existing mid-trend portfolio review.
2. Caller passes the returned `review_result` to the integration adapter.
3. Adapter extracts `portfolio_summary`, `review_rows`, `markdown`, and `paths`.
4. Adapter writes a run evidence bundle using `write_evidence_bundle()`.
5. Adapter appends one `ExperimentRecord` to `experiment_registry.jsonl`.
6. Adapter converts review rows into `ResearchSignalRecord` rows.
7. Adapter converts review rows into `AttributionCard` rows.
8. Adapter returns a dictionary of sidecar artifact paths and record counts.

## Artifact Mapping

Run evidence bundle:

- `run_type`: `mid_trend_portfolio_review`
- `run_id`: derived from `trade_date` and `strategy_variant`
- `research_question`: whether current mid-trend candidates should be held,
  deprioritized, or discussed under the current research and regime context
- `sample_window`: single review date for the first slice
- `universe`: review row count and strategy variant
- `feature_set`: research support, coverage, risk disclosure, regime, layer, and
  rank fields present in review rows
- `label_definition`: review label generated by the existing workflow
- `input_artifacts`: existing paths from the review result when available
- `output_artifacts`: existing CSV/Markdown review paths plus generated sidecars

Experiment registry:

- `experiment_id`: `mid-trend-review-infra-<trade_date>-<strategy_variant>`
- `objective`: standardize evidence for mid-trend review
- `hypothesis`: standardized evidence improves review reproducibility and
  coverage-gap diagnosis
- `reuse_status`: `monitor_only`

Research signals:

- `research_support_score` from `research_support_score_pit`
- `coverage_freshness_score` from report coverage columns
- `risk_disclosure_score` from PDF risk-section coverage

Missingness is explicit. Missing report coverage becomes `signal_value=None`
with a `missingness_reason`, not a negative score.

Attribution cards:

- `research_coverage_gap` when a row lacks fresh research support.
- `market_regime_mismatch` or `industry_regime_mismatch` when available regime
  context conflicts with a weak review label.
- `drawdown_control` when review evidence contains drawdown-control fields.
- `replacement_failure` only when replacement evidence is explicitly present.

Each attribution card must include evidence and a counterfactual.

## Error Handling

- Empty review rows produce valid empty signal/card files plus a run card warning.
- Missing `paths` in `review_result` is allowed; artifact paths fall back to the
  generated sidecar paths.
- Missing required review context raises a clear validation error before writing
  partial artifacts.
- Future source timestamps are not inferred in this slice; integration uses
  `trade_date 15:00:00` as availability timestamp unless a source timestamp
  column is explicitly present.

## Testing

Focused tests should cover:

- A toy mid-trend review result writes all sidecar artifacts.
- Research signals distinguish missing coverage from negative evidence.
- Low-priority hold with missing research support creates a
  `research_coverage_gap` attribution card.
- The run evidence bundle includes existing review CSV/Markdown paths.
- Empty review rows produce empty sidecar artifacts and a warning.

Verification command:

```bash
/Users/xiwei/stock_research/.venv/bin/python -m pytest \
  tests/test_research_infra_mid_trend_integration.py \
```

## Implementation Boundary

Implementation should happen in a new integration worktree, not in the dirty
main worktree. The implementation branch should start from
`method-infra-first-slice` and bring in only the mid-trend review module surface
needed for the adapter tests.

If the needed mid-trend modules remain uncommitted in the main worktree, the
first implementation slice should test the adapter against a toy
`review_result` dictionary instead of importing uncommitted modules.

## Success Criteria

- Existing method-layer tests keep passing.
- New integration tests pass.
- Existing mid-trend review behavior is unchanged.
- Sidecar artifacts can be reviewed without database access.
- The integration remains review-only and does not imply trade execution.
