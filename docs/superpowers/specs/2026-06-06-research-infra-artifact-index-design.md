# Research Infra Artifact Index Design

## Goal

Add a lightweight evidence index so every `research_infra` evidence bundle
generated by review workflows can be discovered, audited, and reused without
walking output directories.

The first integration target is mid-trend portfolio review, but the index should
be generic enough for later watchlist, TopN, factor evaluation, and daily review
runs.

## Current Context

The platform now has method-layer artifacts:

- run card / evidence bundle
- experiment registry
- feature registry
- research signal records
- factor evaluation cards
- attribution cards
- mid-trend sidecar writer and opt-in review wrapper

The real mid-trend runner can now opt in to `research_infra` sidecar generation
from the main worktree. The missing operational piece is discoverability: once
sidecars are written under a run output directory, later tools need a stable
place to find the latest or historical evidence bundles.

## Scope

Included:

- Add a generic artifact index contract in `stock_research.research_infra`.
- Store one JSON object per generated evidence bundle.
- Append index records to a JSONL file.
- Deduplicate records by deterministic `run_id` plus `research_infra_dir`.
- Add a helper that can update the index after
  `write_mid_trend_research_infra_artifacts(...)`.
- Keep index writing opt-in through the existing `write_research_infra` path.

Excluded:

- Dashboard UI.
- Database tables or migrations.
- Changing review labels, ranking, or evidence generation logic.
- Trading, broker, order, position, cash, or account behavior.
- Importing ML4Trading code.

## Proposed Index File

Default path:

```text
<output_dir>/research_infra_index.jsonl
```

For a mid-trend run where `output_dir=outputs/research`, this becomes:

```text
outputs/research/research_infra_index.jsonl
```

Each line is one bundle record.

## Record Schema

```python
@dataclass(frozen=True)
class ResearchInfraArtifactIndexRecord:
    run_id: str
    run_type: str
    trade_date: str
    strategy_variant: str
    created_at: str
    research_infra_dir: str
    run_card_json_path: str
    research_signals_json_path: str
    attribution_cards_json_path: str
    attribution_cards_md_path: str
    experiment_registry_path: str
    metrics: dict[str, Any]
    warnings: list[str]
    caveats: list[str]
```

For the first slice, `trade_date` and `strategy_variant` are explicit fields
because mid-trend review is the first consumer. Later, if non-strategy research
runs need the same index, they can use empty strings for fields that do not
apply rather than forcing a broader schema now.

## Writer API

Add:

```python
def append_artifact_index_record(
    path: str | Path,
    record: ResearchInfraArtifactIndexRecord,
) -> None:
    ...
```

Behavior:

- Creates parent directories.
- Reads existing records if the index file exists.
- If a record with the same `(run_id, research_infra_dir)` already exists, do
  not append a duplicate.
- Writes compact JSONL with sorted keys.

Add:

```python
def read_artifact_index(
    path: str | Path,
) -> list[ResearchInfraArtifactIndexRecord]:
    ...
```

Behavior:

- Returns `[]` when the file does not exist.
- Ignores blank lines.
- Raises normal JSON/type errors for malformed lines.

## Mid-Trend Integration

Extend `write_mid_trend_research_infra_artifacts(...)` with:

```python
artifact_index_path: str | Path | None = None
```

Default behavior:

- If `artifact_index_path is None`, no index file is written.
- Existing returned artifact dictionary is unchanged except for the optional
  addition of `artifact_index_path` when index writing is enabled.

Enabled behavior:

- Caller passes `<output_dir>/research_infra_index.jsonl`.
- The adapter writes one index record after sidecars and run card are written.
- Returned artifact metadata includes:

```python
{
    "artifact_index_path": "<output_dir>/research_infra_index.jsonl"
}
```

The runner wrapper can compute the default index path from its normalized
`output_dir` when `write_research_infra=True`.

## Data Flow

1. Review runner writes the normal review CSV/Markdown.
2. Runner calls the research-infra wrapper with sidecar writing enabled.
3. Mid-trend sidecar writer writes signals, attribution cards, experiment
   registry, and run card under `<output_dir>/research_infra/`.
4. Sidecar writer appends one record to
   `<output_dir>/research_infra_index.jsonl`.
5. CLI prints the index path if present in returned metadata.

## Error Handling

- If index writing is enabled and fails, the run should fail. The user explicitly
  requested evidence generation, and an incomplete evidence trail should not be
  silently accepted.
- If the index file contains malformed JSON, reading should raise so the caller
  sees the index corruption.
- Duplicate deterministic records should not raise; they should be skipped.

## Testing

Focused tests:

- Append and read a single index record.
- Re-appending the same `(run_id, research_infra_dir)` does not duplicate.
- Reading a missing index returns `[]`.
- Mid-trend sidecar writer writes `artifact_index_path` when enabled.
- Re-running the same mid-trend review keeps the index readable and deduped.
- Runner/CLI returns and prints the index path when `--write-research-infra` is
  enabled.

## Success Criteria

- Every enabled mid-trend research-infra run can register one discoverable index
  record.
- Repeated runs do not bloat the index with duplicate deterministic records.
- Existing sidecar generation still passes.
- Existing default review behavior remains unchanged when
  `write_research_infra=False`.
- No dashboard, database, or execution behavior is introduced.
