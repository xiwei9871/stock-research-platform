# 全市场滚动板块超跌反弹预测设计

## 目标

把当前固定消费板块的超跌选股，升级为每日滚动的全市场预测系统：每天先识别真正处于超跌状态且具备修复条件的行业/概念板块，再在板块内部评估个股未来 3—5 个交易日的反弹潜力，并用后续真实表现持续验证和修正。

首轮历史验证从 `2026-07-21` 开始，但锚点日期必须是参数，不得写死。每个锚点只使用该日及以前已经落库的数据，未来数据只用于结果评价。

## 设计原则

1. **数据库唯一数据源**：策略链路只读取数据库和已封存的本地证据；缺失数据只生成独立回填任务，不在策略中调用外部源。
2. **滚动快照不可变**：每天生成新的预测快照，不覆盖历史预测；次日修正通过新快照与旧快照的关联表达。
3. **先板块、后个股**：先判断板块是否值得做反弹，再进行个股排序，避免把消费、科技等任何单一板块写死。
4. **修复与超跌分离**：上涨后不机械删除，区分已确认修复、修复后仍有空间和已经失去超跌属性。
5. **严格防未来函数**：特征截止日等于预测锚点；1/3/5 日结果只能进入评价和后续参数校准。

## 运行流程

```text
锚点 T
  └─ 市场状态判断
      └─ 全行业/概念板块超跌与修复潜力评分
          └─ 板块门槛通过
              └─ 板块内个股修复潜力 + 3—5 日启动能力评分
                  └─ 生成 T 日预测快照

锚点 T+1
  ├─ 评价 T 日的 1 日表现
  ├─ 更新 T 日候选生命周期
  └─ 基于 T+1 数据生成新的 3—5 日预测快照

锚点 T+3 / T+5
  └─ 完成历史预测评价，进入滚动验证统计
```

## 第一层：市场状态

每日计算大盘和风格背景：指数趋势、涨跌宽度、涨停/跌停结构、波动率、成交活跃度、成长/价值与大盘/小盘相对强弱。输出 `risk_on`、`neutral`、`risk_off` 和 `panic_rebound_watch` 等状态。

市场状态不是单独的选股分数，而是板块门槛的环境约束：极端风险收缩时降低候选数量或进入观察模式，避免把普遍性下跌误判为板块反弹机会。

## 第二层：板块状态

行业和概念板块全部从数据库的有效映射生成。每个板块在锚点日计算：

- 5、10、20 个交易日收益和相对大盘收益；
- 60、120、252 个交易日回撤与价格位置；
- 成分股下跌宽度、跌破 MA20/MA60 比例和新低比例；
- 成交额/换手活跃度、波动和内部离散度；
- 最近 1—5 日反弹幅度及从低点的修复比例；
- 成分股基本面质量、估值修复空间和风险集中度。

板块输出以下互相独立的字段：

- `sector_oversold_score`：跌幅和广度造成的超跌程度；
- `sector_repairability_score`：基本面、估值和历史反弹特征支持的修复潜力；
- `sector_direction_score`：短期方向、成交和市场状态支持的启动能力；
- `sector_recovery_state`：`fresh_oversold`、`repairing`、`repaired`、`structurally_weak`、`unknown`；
- `sector_gate_status`：`confirmed`、`watch`、`blocked`。

推荐的板块硬门槛是：超跌程度达标、修复潜力达标、数据覆盖完整，并且没有被市场状态或结构性走弱状态否决。板块评分用于候选排序，不替代硬门槛。

## 第三层：个股状态与排序

对通过板块门槛的板块，使用现有消费 V2 已验证的通用组件：修复潜力、技术启动、历史延续性、剩余价格空间、资金推动效率、股性和流动性。个股排序由以下部分组成：

1. 板块门槛通过；
2. 个股基本面/估值修复潜力；
3. 个股未来 3—5 日启动能力；
4. 个股弹性、股性、市值和交易可实现性；
5. 个股相对板块的超跌程度和剩余空间。

个股生命周期包括：

- `new_oversold`：新进入超跌池；
- `expected_repair`：存在修复预期但尚未确认；
- `confirmed_repair`：价格和板块表现已经确认修复；
- `repair_with_residual_space`：已经反弹但距离长期价格空间仍远；
- `invalidated`：基本面、技术或市场环境使修复逻辑失效。

上涨 10%—20%只触发状态重估，不直接删除。是否移出新超跌池由修复比例、距 1—2 年高点的空间、板块剩余超跌程度和市场方向共同决定。

## 滚动快照与评价

每个锚点生成一个不可变快照，至少包含：

- `anchor_date`、`data_cutoff`、策略版本和数据版本；
- 市场状态和板块状态；
- 板块排名、板块门槛和板块覆盖；
- 个股排名、生命周期、预测分数和预测区间；
- 预测未来 1、3、5 个交易日收益的字段；
- 前一快照中的候选状态和排名，用于计算 `rank_change`、`state_change` 和 `sector_change`。

对每个快照分别记录：

- 1/3/5 日上涨比例；
- 平均、中位数和分位收益；
- 达到 3%、5%、7% 的比例；
- 板块命中率和板块内个股命中率；
- 新候选、延续候选、移除候选和漏选候选；
- 不同市场状态、板块状态下的条件表现。

历史回测从 `2026-07-21` 开始，每天向后滚动；不能把未来的 3/5 日结果用于当天排序。只有完成观察窗口并经过规定的信息滞后后，结果才可用于参数校准。

## 数据覆盖和回填

板块映射、行业成员、日线历史、股本、财务、估值和市场状态输入均执行数据库预检。缺少行业/概念映射时，不能静默漏掉板块，必须生成独立的板块映射回填任务。5 分钟线只用于事后表现诊断，不作为候选生成的强制输入。

## 性能与发布

采用“全板块轻量扫描 + 通过门槛板块的个股深度评分 + 特征缓存”的路径。每天生成一个新快照，目标运行时间小于 15 分钟，硬上限 60 分钟。正常运行和缺数阻断均不覆盖历史快照。

首轮验证分两步：

1. 冻结 `2026-07-21` 至最新可用交易日，回放每日滚动结果；
2. 单独核验 2026-07-30 的科技、芯片、CPO、算力板块是否能够被板块层自动识别，并与消费板块结果并列比较。

## 验收标准

1. 每个历史锚点只使用 PIT 可见数据；未来字段不能进入当日特征。
2. 所有数据库中有完整映射的板块都被扫描，并有明确的通过/观察/阻断状态。
3. 缺失板块映射或行情数据时生成回填任务，不调用外部源、不发布伪排名。
4. 每个快照可以独立复现，并能关联到 1/3/5 日真实结果。
5. 能解释候选为什么新增、延续、确认修复或退出。
6. 7月21日开始的滚动回放和7月30日科技板块专项核验通过。
