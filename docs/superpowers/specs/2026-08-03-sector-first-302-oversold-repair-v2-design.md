# 板块优先的全量302概念超跌修复策略 v2 设计

## 目标

把现有“混合板块股票总榜”升级为“全量概念板块独立研究 + 板块内独立选股 + 严格PIT滚动验证”的策略。每个冻结日对数据库中截至该日可见的全部302个超跌概念板块计算板块状态，再在每个板块内部生成候选股票；不再因为全局门槛把核电等当日突然修复的板块提前丢弃。

优化目标是未来3—5个交易日的：

- 板块上涨比例；
- 板块平均/中位数修复幅度；
- 板块内Top5/Top10股票的上涨比例和收益；
- 确认修复与预期修复两类的差异。

不以事后绝对股票排名作为唯一目标。

## 范围与非目标

范围：

- 全部302个概念板块；
- 2025—2026为主要股价回看范围，仍保留策略配置的60/120/252交易日技术窗口；
- 每个冻结日独立输出板块状态和板块内股票排名；
- 以数据库为唯一策略运行数据源；
- 支持7/31冻结、预测8/3—8/7这类滚动窗口。

非目标：

- 不在本轮引入机器学习黑盒模型；
- 不把不同板块的股票合并成唯一全市场Top30作为主产物；
- 不用策略运行时访问baostock、AkShare或其他外部行情源；
- 不用未来目标窗口数据回写历史快照。

## 当前基线与问题

现有 `rolling_oversold` 已提供：

- 60/120/252日回撤和价格位置；
- 5/10/20日收益；
- 最近20日低点到当前的恢复比例；
- 20日上涨比例、新低比例、20/60日均线状态；
- 近5日/20日成交额比；
- PIT finance/valuation加载、不可变快照和滚动outcome评估。

需要改进：

1. 板块状态与股票门控耦合，`sector_gate_status=blocked` 会使板块内股票完全消失；
2. 最近低点日期、距低点的恢复交易日数、低点恢复幅度没有作为明确输出字段；
3. 当前量能主要是成交额比，不包含显式的成交量比和量价配合状态；
4. 没有全量302板块的独立TopN产物；
5. 运行时需要把一次全量加载和批量计算与板块输出分离。

核电回归案例：`ths:300238`在2026-07-31相对2026-07-30上涨约2.24%，但旧门控可能使其股票候选缺失。v2必须保留它的板块状态并允许板块内研究。

## 设计

### 1. PIT数据与板块宇宙

对冻结日 `t`：

- 所有行情、成员关系、状态、财务和估值数据必须满足 `data_date <= t`；
- 成分股关系按 `start_date <= t < end_date` 解释；
- 302板块来自数据库中的THS概念板块历史，`concept_drawdown_over24_2026-08-01.csv`只作为已冻结验证产物和对照，不作为运行时外部数据源；
- 不同板块允许同一股票重复出现，每个板块排名独立；
- 缺失板块历史或成分关系时保留板块行并标注数据状态，不静默删除。

### 2. 板块特征

每个板块在冻结日生成以下显式字段。

超跌与位置：

- `sector_high_close_60d/120d/252d`
- `sector_high_date_60d/120d/252d`
- `sector_low_close_20d/30d/60d`
- `sector_low_date_20d/30d/60d`
- `sector_drawdown_60d/120d/252d`
- `sector_price_position_252d`
- `sector_recovery_from_low_20d/30d/60d`
- `sector_days_since_low_20d/30d/60d`

短期修复：

- `sector_return_1d/3d/5d/10d/20d`
- `sector_rebound_from_anchor_low`
- `sector_ma5/ma10/ma20`
- `sector_ma5_slope_5d`
- `sector_ma10_slope_10d`
- `sector_ma5_cross_ma10`
- `sector_close_above_ma5/ma20`

量价与广度：

- `sector_amount_ratio_5_20`
- `sector_volume_ratio_5_20`
- `sector_up_ratio_1d/5d/20d`
- `sector_above_ma5_ratio/above_ma20_ratio`
- `sector_new_low_ratio_20d/60d`
- `sector_leader_return_1d/3d/5d`
- `sector_leader_breadth`
- `sector_dispersion_20d`

其中量能字段必须明确区分成交额比和成交量比；如果某数据源缺失成交量，只允许标记缺失，不用成交额静默替代。

### 3. 板块状态和研究资格解耦

保留旧的`sector_gate_status`用于兼容，但新增两个概念：

- `sector_recovery_state`：fresh_oversold、expected_repair、repairing、confirmed_repair、failed_repair、unknown；
- `sector_research_eligibility`：eligible、watch、blocked_data。

`blocked_data`只表示数据不能支撑研究，不表示板块本身弱。板块状态表必须保留全部302行。

确认修复至少需要：

- 板块仍有足够的超跌空间；
- 1/3/5日收益改善；
- 上涨广度达到门槛；
- 量能或成交额改善；
- 均线/趋势状态不再继续恶化。

预期修复可以只要求超跌、估值/基本面支持和未明显失效，但必须标注技术确认不足。

### 4. 板块内股票评分

每个板块独立计算股票分数：

- 个股超跌深度和距高点空间；
- 个股距自身低点的修复幅度；
- 基本面/估值质量；
- 量价趋势和成交量比；
- 股性、弹性、涨停历史；
- 流动性、ST、停牌、涨跌停约束；
- 板块修复状态贡献。

输出`sector_stock_rank`，而不是跨板块的唯一`stock_rank`。默认每个板块输出Top10，完整候选保留在机器文件中。确认修复和预期修复分开标注。

### 5. 预测与滚动验证

冻结日 `t`只预测之后5个交易日：

- 7/27 → 7/28、7/29、7/30、7/31、8/3；
- 7/31 → 8/3、8/4、8/5、8/6、8/7。

每个板块和板块内股票都保存不可变预测快照。新行情落库后只新增：

- 每个目标日的完成/待验证状态；
- 板块上涨比例、平均收益、中位数收益；
- Top5/Top10命中率；
- 确认修复/预期修复分组表现。

校准下一冻结日时，只使用此前已经完成的结果，不回写历史名单。

### 6. 批量架构与性能

一次冻结日按以下顺序运行：

1. 一次加载全部PIT数据；
2. 一次批量计算全部302板块特征；
3. 一次批量聚合成分股广度和量价指标；
4. 一次批量计算个股因子；
5. 按板块分组排名并写出结果；
6. 单独追加验证层。

性能目标：

- 全量302板块单冻结日硬预算不超过3600秒；
- 热缓存后目标为几分钟级；
- 5个冻结日滚动回放目标不超过900秒；
- 不允许为每个板块重复执行完整数据库加载。

## 产物

每个冻结日：

- `sector_daily_board.csv`：全部302个板块状态；
- `sector_stock_candidates.csv`：板块内Top10和完整候选；
- `sector_repair_summary.md`：按修复状态、超跌深度和研究价值排序；
- `sector_snapshot_manifest.json`：PIT截止日、配置、行数、哈希、运行时间；
- `sector_backfill_requests.csv`：缺失数据的独立回填请求。

滚动验证：

- `sector_walk_forward_detail.csv`；
- `sector_walk_forward_summary.csv`；
- `sector_stock_walk_forward_detail.csv`；
- `sector_stock_walk_forward_summary.csv`。

## 验收标准

1. 冻结日为2026-07-31时，所有特征只读取2026-07-31及之前数据；
2. 302个板块均有状态行，不因股票门控被静默删除；
3. 核电`ths:300238`在7/31板块报告中出现，并记录约2.24%的单日修复；
4. 每个板块均可生成独立Top10或明确的数据缺口状态；
5. 量能比、成交量比、低点恢复幅度、低点日期和趋势字段可追溯；
6. 7/27—7/31滚动窗口无未来函数，已完成和pending状态正确；
7. 新旧版本能输出配对的上涨比例、平均收益和命中率比较；
8. 全量单冻结日运行不超过3600秒，且运行日志包含load、sector、stock、publication分阶段耗时；
9. 单元、PIT、快照不变性、核电回归和性能验收全部通过。
