# LHB 名称补全与跌停风险门控设计

## 1. 背景与问题

2026-07-14 的 `LHB Shortline Combo Top5` 出现两个问题：

1. `001399.SZ` 显示为 `CN:SZ:001399`，没有显示证券名称“惠科股份”。当天龙虎榜源表已有正确名称，但 `core.asset_master` 和 `public.asset_master` 尚未收录该证券；策略发布产物也没有保留源名称，仪表盘最终只能回退到资产 ID。
2. 惠科股份当日收盘跌幅约 `-9.99%`，仍以 69.4 分排入 Top5。现有 LHB 基础分奖励净买比例、净买额、机构买入、重复上榜、反转和成交确认，并扣除一日游风险与高收低走，但没有对接近跌停的收盘状态设置硬门控。

历史回放说明第二个问题不是合理的次日上涨信号：

- 全部策略 Top5 样本：次日上涨率 `53.37%`，次日平均收益 `+0.95%`。
- Top5 中当日跌幅不小于 7% 的样本：次日上涨率 `40.79%`，次日平均收益 `-1.26%`。
- Top5 中接近跌停的样本：次日上涨率 `39.80%`，次日平均收益 `-1.54%`，3 日平均收益 `-3.39%`，5 日平均收益 `-3.89%`。
- 接近跌停且得分 65–75 的样本：次日上涨率 `39.13%`，次日平均收益 `-1.49%`，中位数 `-3.21%`。

因此，“接近跌停但龙虎榜净买”为风险观察事件，不应占用 Top5 重点复盘名额。

## 2. 目标

本次修改同时根治名称和风险筛选问题：

1. 新证券即使尚未进入资产主表，策略页面也能显示龙虎榜源中的正确证券名称。
2. 资产名称同步不再只更新已有记录，能够补入合法的新证券。
3. 接近对应市场跌停阈值的股票不再进入 `top5_focus`，但保留原始评分和研究记录。
4. 被降级的候选明确标记原因，Top5 从后续合格候选中递补，保持最多五只。
5. 重跑 2026-07-14 发布结果后，“惠科股份”名称正确，且该股票不再位于 Top5。

## 3. 非目标

- 不删除接近跌停的龙虎榜记录。
- 不把风险门控解释为自动交易或卖出指令。
- 不修改 LHB 原始评分公式及历史原始数据。
- 不因为本次修复重构其他策略的排名逻辑。
- 不以股票名称作为证券唯一标识；唯一标识仍为标准化 `asset_id` / `ts_code`。

## 4. 总体方案

采用两个互相独立、在发布层汇合的组件：

```text
AKShare 证券列表 ──> 资产主数据 upsert ──┐
                                         ├─> 名称解析 ─> 发布产物 ─> 仪表盘
当日 LHB 源名称 ─────────────────────────┘

当日行情 pct_chg + 证券制度 ─> 跌停风险分类 ─> Top5 资格门控 ─> 排名递补
原始 LHB 特征 ───────────────────────────> 原始评分保留 ───────┘
```

名称解析解决“显示什么”，风险门控解决“进入哪个观察层”。两者不互相依赖。

## 5. 名称补全设计

### 5.1 资产主数据同步

扩展 `sync_chinese_stock_names_from_akshare`：

- 对已存在证券更新中文名称。
- 对不存在但代码和交易所可合法标准化的证券执行 upsert，补入 `public.asset_master` 与 `core.asset_master`。
- 沿用现有代码标准化逻辑，生成 `ts_code`、交易所和标准 `asset_id`。
- 单条异常不能中断整批同步；记录无法标准化的代码数量和样例。
- 同步应幂等，重复执行不产生重复证券。

### 5.2 发布层名称解析

策略发布不能假定资产主表永远完整。每个候选名称按以下优先级解析：

1. 策略候选自身已有且非空的 `stock_name`。
2. `core.asset_master` 中的当前名称。
3. 同交易日 `market.lhb_top_list_daily` 中同一证券的非空名称。
4. 最后才回退到标准化证券代码或 `asset_id`。

发布产物显式写入 `stock_name`。仪表盘优先使用该字段，现有资产主表补全仅作为兼容兜底。这样即使新股同步暂时失败，当日 LHB 页面仍可显示源名称。

### 5.3 名称数据约束

- 空串、纯空白和与 `asset_id` 完全相同的值视为无有效名称。
- 同日同证券出现多个名称时，选择非空的最后有效值；若存在冲突则记录告警，发布继续。
- 名称只用于展示，不能改变去重、连接或排名键。

## 6. 跌停风险门控设计

### 6.1 制度感知阈值

根据证券所属板块和特别处理状态判定“接近跌停”：

| 证券制度 | 接近跌停阈值（当日 `pct_chg`） |
|---|---:|
| 沪深普通主板 | `<= -9.5%` |
| ST / *ST | `<= -4.8%` |
| 创业板 / 科创板 | `<= -19.0%` |
| 北交所 | `<= -29.0%` |

板块优先从标准代码和市场字段确定；ST 状态优先从当日有效证券名称识别。阈值留出行情四舍五入和价格最小变动造成的偏差。

若板块无法识别，采用普通主板 `-9.5%` 的保守阈值，并记录分类告警。若 `pct_chg` 缺失，不凭空判定跌停，保留现有资格并记录数据缺失提醒。

### 6.2 排名行为

风险门控在原始评分计算之后、Top5 选择之前执行：

- 保留 `raw_score`，不得把分数改成零或覆盖历史评分。
- 命中接近跌停阈值的候选设置 `top5_eligible = false`。
- 该候选从 `top5_focus` 降级为 `risk_watch`。
- 写入机器可读原因 `near_limit_down_followthrough_risk`。
- 写入可读解释，包含当日涨跌幅、适用制度和阈值。
- Top5 按原始分数从剩余 `top5_eligible = true` 的候选依次递补。
- 若合格候选不足五只，Top5 可以少于五只，不允许用被门控候选凑数。

门控仅影响展示层级和排名资格，不删除记录，也不阻止后续研究该类风险样本。

### 6.3 数据来源与时点

门控只使用交易日收盘时已经可获得的数据：

- 当日 `pct_chg`。
- 证券代码、市场和板块。
- 当日有效证券名称中的 ST 标记。

不使用次日或未来收益，避免前视偏差。历史收益仅用于证明和校准规则。

## 7. 发布数据流

LHB 日终发布流程调整为：

1. 加载 LHB 因子特征和技术行情，同时带入 `pct_chg`。
2. 计算现有 LHB 原始分数。
3. 批量解析候选证券名称。
4. 根据代码、名称和 `pct_chg` 计算跌停制度、阈值和风险标志。
5. 对合格候选按原始分数排序，生成最多五个 `top5_focus`。
6. 将被门控候选保留为 `risk_watch`；其他候选保持既有层级规则。
7. 在 review、score audit 和仪表盘消费的发布产物中写入名称及门控审计字段。

发布产物必须提供以下审计语义：

- `stock_name`
- `raw_score`
- `top5_eligible`
- `risk_gate_code`
- `risk_gate_reason`
- `price_limit_regime`
- `near_limit_down_threshold`
- `pct_chg`

若现有产物已有完全等价字段，实施时复用该字段；否则使用上列字段名新增，禁止为同一语义维护两套字段。

## 8. 错误处理与可观测性

- 资产同步：输出新增、更新、跳过、失败数量；失败样例去重并限制日志体积。
- 名称解析：统计候选总数、源字段命中数、主表命中数、LHB 兜底命中数和最终回退数。
- 风险门控：统计各价格制度候选数、门控数和 Top5 递补数。
- 单只证券的名称或制度识别异常不得使整日发布失败；使用明确兜底并输出告警。
- 行情源整体缺失、导致所有候选均无法取得 `pct_chg` 时，发布标记为降级状态并产生高优先级告警，不静默宣称风险门控已生效。

## 9. 测试设计

### 9.1 名称测试

- 候选自带名称时优先保留。
- 候选名称为空、主表有名称时使用主表名称。
- 主表缺失、当日 LHB 有名称时使用 LHB 名称。
- 三层均无名称时才回退代码。
- 资产同步可插入新证券、更新旧名称，并且重复运行幂等。
- 名称冲突不影响证券主键和排名。

### 9.2 风险门控测试

- 普通主板 `-9.50%` 命中，`-9.49%` 不命中。
- ST `-4.80%` 命中，普通主板同跌幅不命中。
- 创业板和科创板 `-19.00%` 命中。
- 北交所 `-29.00%` 命中。
- `pct_chg` 缺失时不误杀，但产生数据缺失标记。
- 命中门控后原始分数保持不变，层级变为 `risk_watch`，原因码正确。
- 原 Top5 第四名被门控后，第六名递补；最终顺序仍按原始分数。
- 合格候选不足五只时不以风险候选补足。

### 9.3 回归与验收

- 其他非 LHB 策略的 review queue 输出不变。
- LHB 未命中门控的候选排名与修改前一致。
- 重跑 `2026-07-14`：
  - `CN:SZ:001399` 显示为“惠科股份”，证券代码仍正确保留。
  - 惠科股份保留 69.4 左右的原始评分审计。
  - 惠科股份不再属于 `top5_focus`，而是 `risk_watch`，原因码为 `near_limit_down_followthrough_risk`。
  - 下一名合格候选递补 Top5。

## 10. 发布与回滚

实施后先运行单元测试和发布层回归测试，再仅重跑 2026-07-14 的 LHB 发布产物进行人工验收。验收通过后应用于后续交易日。

如果出现误分类，可单独停用 Top5 资格门控并保留新增审计字段；名称双层补全可独立继续运行。回滚不需要修改原始 LHB 数据或历史原始评分。

## 11. 完成标准

以下条件全部满足才算完成：

1. 新证券名称同步支持幂等 upsert，发布层具备 LHB 当日名称兜底。
2. 四类价格制度阈值均有自动化边界测试。
3. 接近跌停候选保留原始评分，但不能进入 Top5，并可被后续合格候选递补。
4. 发布产物可审计名称来源、风险原因、适用制度和阈值。
5. 相关测试通过，且 2026-07-14 回跑结果满足名称与排名验收要求。
