## 2. 对比方法

- 每个 POC 设两组，每组由一个独立子代理执行一次。执行时不联网，只读取指定文件，只写一个输出文件。
  - **官方组**：严格按官方 SKILL.md 和 Agent 提示词执行，允许输出 `[UNSOURCED]`。
  - **A 股适配组**：采用"主题 → 节点 → 公司 → 证据 → 可证伪假设 → 跟踪指标"结构，包括资料清单、准则口径和管理层表述分开写、记分卡，并把 PIT 判定交回确定性规则。
- **数字核验**：从输出中抽取 20 个数字或日期，回查输入文件，20 个全部命中。其中 3 个在原文中被 PDF 换行截断或日期写法不同，人工核对后一致。

## 4. 观察（方法层面）

**官方组的失分点**
- 估值、市场份额、TAM、一致预期、业绩会问答等章节无法执行，大约 40% 的内容只能写 `[UNSOURCED]`。
- 流程要求列出 8-15 家同业公司，证据不够。
- thesis-tracker 默认要求填写持仓方向和目标价，子代理只能自行假设。
- 输出是叙述性文字，节点判定没有显式状态字段。

**官方组的可取之处**
- `[UNSOURCED]` 纪律确实生效，没有编造任何数字。
- 护城河评分表和观察信号（signposts）提供了信息增量。

**适配组的可取之处**
- 节点表、证据表、可证伪假设、缺口分类可以直接映射到 `ResearchEnvelope`。
- 每条论点都有证伪条件，并写明下一个可检验的披露节点。
- 能分清准则口径和管理层表述。

**适配组的失分点**
- 摘录行没有 ID，只能按行序引用。
- 篇幅超出目标。

**顺带发现的数据现象**
- 两条数据现象最初被报为数据缺陷。重新核对后，已分别改判为"PIT 语义未写清"和"ID 命名空间不同"，见主报告 §6、§7。

## 5. 限制与未验证项

- 每组 n=1，只覆盖一个主题、一家公司。
- 由单人评分，没有盲评。适配组的提示词是评估者写的，并且嵌入了平台证据模型的知识，所以分差里有一部分来自"提示词更贴近评分标准"，不能全部归因于方法本身。
- 确定性 CAP-01 dossier 引擎的基线对照没有完成：它在运行时需要读取的数据库处于恢复模式。此项为 `NOT_VERIFIED`。没有写入，也没有重试。
- 官方组在有付费数据时的表现没有验证，此项为 `INSTALLATION_REQUIRED` + `DEPENDENCY_REQUIRED`。
- 产品价值要通过主报告 §11.6 的盲评验收来证明。
